The browser agent that's cheap to run and safe by default.

Most of the web has no API. Selfbrowse lets your AI open pages, fill in forms and bring back answers in a real browser, on any model, including one on your own laptop. It is open source and runs on your machine, with guardrails and tracing built in.

  • 4–7× fewer tokens than browser-use
  • Guardrails built in
  • Runs local models
  • Open source, MIT

Why it costs less: the model reads a list, not a screenshot

Many agents send the model a screenshot, or a large slice of the page, on every step. Selfbrowse sends a short numbered list of what a person could click or type, and the model answers with a number. Only the newest list stays in the conversation.

One step, start to finish

  1. Read the page

    Selfbrowse lists what is visible and usable: links, buttons, fields, dropdowns and headings, including those inside iframes and web components.

  2. Ask the model

    The model gets the task, the list and about fifteen small tools. It answers with one call, such as type {"ref": 2, "text": "lamp"}.

  3. Check and act

    Guardrails look at the action first. Then Selfbrowse clicks or types for real, in Chromium or your own Chrome.

  4. Show what changed

    The new page goes back as a fresh list, until the model calls done with its answer.

Lowest token cost, measured

Same tasks, same browser, four models. We ran Selfbrowse and browser-use on six tasks in a local test shop: read a fact, search, navigate, add to cart past a cookie banner, log in, and find an item across pages. A server checked the result of each task, and one proxy counted every token sent.

What this shows

Selfbrowse sent 4 to 7 times fewer tokens on every model, and was faster on each. It also passed more tasks with the weaker models. With the strongest local model, both passed everything.

browser-use made fewer model calls on strong models because it batches several actions per turn. Selfbrowse sends less per call but makes more calls.

What it does not show

  • Six tasks on a test shop say little about hard real-world sites.
  • Local models ran each task once, so single differences are anecdotal.
  • browser-use ran with default settings. Its three muse-glimmer failures were 300-second timeouts, not wrong answers.
  • The Llama 3.1 rows come from two different runs, with two extra live-site tasks.

The harness and raw results are in benchmarks/compare, so you can rerun it on your own models.

What the agent can do

The tool set is small on purpose. Every tool description is sent with every call, so each one has to earn its place.

goto
Open a URL.
click
Click an element from the list by its number.
type
Type into a field, and press Enter if asked. Secrets go in as <secret:name>.
select
Pick an option in a dropdown by its text or value.
read
Get the text on screen, when the answer is a fact rather than a control.
find
Jump to a word on a long page and see the text around it.
scroll, back, wait, press
Move around, go back, let the page load, press a key.
switch_tab, close_tab
Move between tabs when a link opens a new one.
ask_human
Hand the window to you for something only a person can do.
done
Finish with an answer, or say why the task cannot be done.

Frames and components

Controls inside iframes, from the same site or another, and inside open shadow roots appear in the same list and work the same way.

Forgiving with small models

Sloppy calls get repaired: {"id": "7"} becomes {"ref": 7} and Down becomes ArrowDown. When a call cannot be fixed, the model is told exactly what to send.

Breaks its own loops

Scrolling in circles, clicking the same button again, or a reply cut off mid-thought each get a short, specific nudge instead of a wasted step.

Security first, guardrails built in

You decide what it may do. Guardrails sit between the model and the browser, and each one turns on with a flag or one line of Python. They can block an action, ask you first, change what the model sees, or stop the run.

Blocked by guardrail AllowedDomains: payments.example.net is not in the allowed list. Choose another approach.

This is what the model is told. It then has to find another way, inside the limits you set.

SafeUrlsalways on
Only http and https. No file:, javascript: or data: pages.
AllowedDomains
Stay on these sites and their subdomains. Redirects elsewhere are sent back.
BlockedDomains
Never visit these sites.
ConfirmRisky
Ask you before a click like Buy, Pay, Delete, Send or Sign out.
RedactPII
Hide emails, phone numbers, SSNs and card numbers from the model behind placeholders like <EMAIL_1>; the real value is typed back on the same site.
PresidioRedactoptional
Also mask names and more with Microsoft Presidio, running on your machine. pip install "selfbrowse[presidio]"
InjectionWatch
Spot “ignore your instructions” text on a page, warn the model, and ask before risky steps.
Budget
Stop past a token, time or dollar limit.
Your own
Subclass Guardrail and override the hooks you need.

Hands off to you when it should

When a CAPTCHA, a login, a 2FA prompt or a payment step appears, Selfbrowse stops, brings the window forward and waits. Finish it yourself and the run carries on from the new page. It never tries to solve a CAPTCHA or guess a password.

Secrets stay out of the prompt

The model writes <secret:password>. Selfbrowse puts the real value in only at the moment of typing, so it never appears in the prompt, the history or the trace.

Observability, plug and play

See exactly what the model was sent and what it answered, without adding a tracing SDK to your code.

--trace
Writes every run to a local JSON-lines file. selfbrowse trace show latest reads it back.
--show-prompts
Prints every request as it is sent, with its token count.
--otel URL
Exports OpenTelemetry spans: one per run, model call and action, with token usage on each.
--otel-content
Adds the system prompt, input messages and the model's reply as standard GenAI attributes. Off by default, because they contain page text.
In Python
on_llm_request and on_step callbacks, and redact_trace to scrub anything written.

It remembers the sites it visits

How much this saves has not been measured yet. Measuring it is the next item on the roadmap.

After a run, Selfbrowse keeps short notes and the clicks that led to success, filed by page pattern. On a later visit, a trusted path is replayed without asking the model at all.

A path is trusted only after it worked for two different tasks, or twice for the same one. Risky clicks are never recorded, and notes expire after 90 days. selfbrowse sites lists what it knows and selfbrowse forget clears a site.

Name a model as provider:model. Local servers need no key, and nothing leaves your machine except the pages you visit.

Try it in a few minutes

Install the package, then a browser for it to drive. Add an extra for OpenTelemetry export or Patchright stealth mode.

Use your installed Chrome with --channel chrome, keep cookies between runs with --profile, and add --headed to watch it work. There are fourteen runnable scripts in examples/, including one that needs no API key.

Install

pip install selfbrowse
playwright install chromium

# optional extras
pip install "selfbrowse[otel]"      # OpenTelemetry export
pip install "selfbrowse[stealth]"   # Patchright
pip install "selfbrowse[mcp]"       # MCP server for VS Code, Claude
pip install "selfbrowse[presidio]"  # mask names with Presidio

Command line

selfbrowse "open news.ycombinator.com and tell me the top story"
selfbrowse --model ollama:qwen3.6 --headed --confirm-risky "..."

Python

from selfbrowse import BrowseAgent
from selfbrowse.guardrails import (
    AllowedDomains, ConfirmRisky, Budget)

result = BrowseAgent(
    "Find the cheapest desk lamp and add it to the cart",
    llm="ollama:qwen3.6",
    guardrails=[
        AllowedDomains(["corner-shop.test"]),
        ConfirmRisky(),
        Budget(max_tokens=50_000),
    ],
).run()
print(result.output, result.usage)
