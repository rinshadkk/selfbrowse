#1The browser agent that tells the model less.

Selfbrowse is an open-source Python agent that does tasks in a real browser. The model gets a short numbered list in place of the page, placeholders in place of your data, and can replay clicks that worked before. That makes it cheap enough for a model on your laptop.

pip install selfbrowse

Python 3.10+, MIT licence, version 0.3. Works with any model that can call tools.

Less page

The model reads a numbered list of what a person could click or type into, and answers with a number. No screenshots and no HTML.

The model reads a list and answers with a number

On every step Selfbrowse lists what is usable on screen: links, buttons, fields, dropdowns and headings. Only the newest list stays in the conversation, so a long task does not drag every earlier page along with it.

Fifteen small tools

Every tool description goes out with every call, so the set is short: goto, click, type, select, read, find, ask_human, done and a few more. About 790 tokens for all of them.

Frames and web components

Controls inside iframes, from the same site or another, and inside open shadow roots appear in the same list and are clicked the same way.

Forgiving with small models

A sloppy call is repaired: {"id": "7"} becomes {"ref": 7}. A model going in circles gets a short, specific nudge.

The model can use your email without reading it

Hiding a value usually breaks the task, because the model cannot type what it cannot see. Selfbrowse gives it a stable placeholder and fills in the real value itself.

  • Passwords never enter the prompt. You name a secret, the model writes <secret:pw>, and the value appears only at the keyboard. It is absent from the history and the trace.
  • Same site only. A placeholder is refused on any site it was not seen on, so a page cannot trick the model into carrying your email elsewhere.
  • Names too, on your machine. --redact-presidio adds Microsoft Presidio for names and more. Nothing is sent to a detection service.
  • It lowers exposure; it is not proof. A value the detector missed is shown to the model. Pair it with --allow-domain, or use a local model so page text never leaves your machine.

Clicks it can replay

After a successful run, Selfbrowse keeps the clicks that led there, filed by page type. Once a path is trusted it is replayed with no model call.

A path is trusted after it worked for two different tasks, or twice for the same one. Risky clicks such as Buy, Pay and Delete are never recorded, and neither is anything you typed. A replay still passes every guardrail, a path that stops working is dropped, and unused ones expire after 90 days.

In small tests on a demo shop with qwen3.8 and Claude Haiku 5.5, replay rarely triggered and we measured no reliable saving. Treat it as experimental.

# what it has learned, clearing one site, turning it off
selfbrowse sites
selfbrowse forget example.com
selfbrowse --no-learn "..."

Measured against browser‑use

The same tasks, model and browser for both, behind one proxy that counts every token. Code checks each result, using the demo shop's state or a fact from the site's own API. The agent's own claim of success is never counted.

What this shows

  • The gap is widest on small and local models, where every token costs time. On those, Selfbrowse also finished each task 3 to 4 times sooner.
  • Selfbrowse makes more model calls than browser-use and sends far less in each one.
  • On Claude Sonnet 5.5 the two were close, and browser-use passed one more task.

What it does not show

  • These are small samples, mostly one run per task. A single flaky result moves a row, so this is not a ranking.
  • browser-use ran with default settings. Its three muse-glimmer failures were 300-second timeouts, and some of its Haiku 4.5 failures were output-format errors, not wrong answers.
  • The harness and raw results are in benchmarks/compare, so you can rerun it on your own models.

One loop between the browser and the model

Guardrails act twice in every step: on the page before the model reads it, and on the action before the browser runs it. Real values exist only where they are typed.

The rest of what ships

Everything here is in the package and turns on with a flag or one line of Python.

Guardrails
Stay on the sites you name, ask before Buy, Pay, Delete or Send, watch page text for injected instructions, and stop at a token, time or dollar budget. Write your own as a small class. Guardrails
Hand-off to a person
When a CAPTCHA, login or 2-step code appears, the run pauses and you finish that step in the browser window. Selfbrowse does not solve CAPTCHAs. Hand-off
Any model
Anthropic, OpenAI, Gemini, Groq, DeepSeek, OpenRouter, Together, Ollama and LM Studio by name. Any gateway that speaks the Anthropic or OpenAI API, or your own model as a small class. Models
A browser for Claude and VS Code
selfbrowse-mcp is an MCP server. The assistant calls browse(task) and gets back only the answer, so pages never enter its context. MCP server
See every prompt
--trace records each model call, reply and action. --otel URL sends OpenTelemetry spans to Jaeger, Phoenix, Langfuse or Tempo, with no code changes. Observability
Evidence of what it did
--screenshots DIR saves a picture after every step with an index page, and --record-video DIR saves a video. The model never gets these images.
Remote browsers
Attach to any browser over CDP with --cdp-url, or start an Amazon Bedrock AgentCore session with --cloud agentcore. Remote browsers
Your Chrome, your profile
--channel chrome --profile DIR uses your installed browser and keeps logins between runs, which gets past many bot checks.

What it does not do yet

Selfbrowse is early software. These are the things we know it does not do well, or have not checked.

  • Not supported yet: file uploads, drag and drop, closed shadow roots, custom dropdowns beyond clicking them, and vision.
  • Hard forms vary. The same Google Flights prompt took 7 steps in one run and more than 30 in two others, so its cost ranged ninefold.
  • Research-style tasks learn little. Most of their clicks are specific to the question.
  • Guardrails reduce risk; they are not guarantees. Pattern matching for personal data and injection misses things, and a hosted model still sees any page text you do not mask.
  • Untested against live accounts: the AgentCore adapter and the Azure and Bedrock model routes are tested with stand-ins.

Run your first task

Install the package and a browser for it to drive, then give it a task. With Ollama there is no key and no cost.

Add --headed to watch it work. There are fourteen runnable scripts in examples, three of which need no API key.

Install

pip install selfbrowse
playwright install chromium

Command line

# a local model through Ollama
selfbrowse -m ollama:qwen3.6:latest "Open news.ycombinator.com and tell me the top story"

# Claude, staying on one site and asking before risky clicks
export ANTHROPIC_API_KEY=your-key-here
selfbrowse --headed --allow-domain example.com --confirm-risky "..."

Python

from selfbrowse import BrowseAgent
from selfbrowse.guardrails import AllowedDomains, RedactPII, Budget

result = BrowseAgent(
    "Find the cheapest desk lamp and add it to the cart",
    llm="ollama:qwen3.6",
    guardrails=[AllowedDomains(["shop.example.com"]), RedactPII(),
                Budget(max_tokens=50_000)],
).run()
print(result.output, result.usage)
