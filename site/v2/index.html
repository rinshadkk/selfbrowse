A browser agent that reads the web as a numbered list.

You describe a task in plain language and Selfbrowse drives a real browser to do it. The model never gets a screenshot or raw HTML. It gets a short list of what can be clicked or typed into, answers with a number, and Selfbrowse remembers what worked on each site.

Install from source

Python 3.10+, MIT licensed, early (0.3). Works with any model that can call tools.

One short list per page

On every step Selfbrowse lists what a person could use on the screen: links, buttons, fields, dropdowns and headings, including those inside iframes and open shadow roots. The model picks one by its number. Only the newest list stays in the conversation, and the tool set is kept small because every tool description goes out with every call.

The tools are goto, click, type, select, press, scroll, back, wait, read, find, switch_tab, close_tab, remember, ask_human and done.

Models

Name a model as provider:model. Built in:

Or bring your own: any object with a complete() method, passed as module:Name or ./file.py:Name. A gateway that speaks the Anthropic or OpenAI API needs no code, only a base URL.

Install and run

Selfbrowse is not on PyPI yet, so install it from source. The package name in pyproject.toml is selfbrowse.

Install

git clone https://github.com/rinshadkk/selfbrowse && cd selfbrowse
python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
playwright install chromium

Or use your installed Chrome with --channel chrome. Extras: stealth, otel, mcp, aws, presidio, bench.

Command line

export ANTHROPIC_API_KEY=your-key-here
selfbrowse "Open news.ycombinator.com and tell me the title of the top story."
selfbrowse -m ollama:qwen3.6:latest "Open news.ycombinator.com and tell me the title of the top story."

The third line uses a free local model through Ollama, with no key. Set your key in your own shell; never paste it into a chat or commit it. Add --headed to watch it work.

Python

from selfbrowse import BrowseAgent

result = BrowseAgent("find the top story on Hacker News", llm="anthropic:claude-haiku-4-5").run()
print(result.output)
print(result.usage)        # input/output/cache tokens and number of model calls

result has success, output, steps, usage, history and error.

New in this version

Tokens on every step

Each step on the command line ends with what it cost, such as [845 in / 65 out]. A step that needed no model call says [0 tokens].

Learning says when it helped

(learned: replayed from saved flow, no model call) marks a replayed click. (learned: used saved notes about this site) marks a step the model chose with saved notes in front of it. In Python, check step.from_cache and step.used_notes.

Elapsed time on the summary

The last line gives steps, model calls, tokens in and out, and how long the run took: 8.4s under a minute, 2m 05s after.

Safer replays

Learning keeps each distinct variant of a flow it has seen, and it never replays a click that changes the page in place, such as “Add to cart”. Only clicks that open another page or dismiss a banner or dialog are replayed.

What it does

The core reading and learning are always on. Everything else is off until you ask for it.

Doing the task

Learning per site
Remembers short facts and the click sequences that worked, per site. A flow trusted for every task, or for the exact same task, is replayed without a model call. Flows that stop working are dropped; unused ones expire after 90 days. --no-learn turns it off.
Hand-off to a person
When a CAPTCHA, login or 2-step code appears, it pauses, rings the terminal bell and lets you act in the visible window, then carries on. It does not solve or defeat CAPTCHAs.
Pop-ups and permissions
Follows new tabs and login windows. Shows JavaScript dialogs to the model and handles them with --dialogs auto|accept|dismiss. Browser permissions such as notifications or location stay off unless you grant them with --permissions.
Remote browsers
Attach to any browser that gives you a CDP address with --cdp-url. --cloud agentcore starts an Amazon Bedrock AgentCore browser session and stops it when done. That adapter is tested with a stand-in client, not yet against a real AWS account.

Keeping things safe

Guardrails
Rules between the model and the browser: --allow-domain and --block-domain, approval before buy, pay, delete, send and sign-out clicks (--confirm-risky), a watch for instruction-like page text (--watch-injection), and token or time budgets. Non-web URLs are blocked by default. You can write your own as a small class.
Personal data masking
--redact-pii hides emails, phone numbers, US SSNs and card numbers behind placeholders like <EMAIL_1>. --redact-presidio adds names and more with Microsoft Presidio, running on your machine. The real value is typed back only on the same site, and your answer shows it. --no-restore masks for good.
Secrets
Give a password by name with SELFBROWSE_SECRET_pw or --secret pw. The model writes <secret:pw> and Selfbrowse swaps in the value at the keyboard. It never appears in prompts, results, history or traces.

Seeing what happened

Traces and prompts
--trace records every model call, tool call and guardrail decision; selfbrowse trace show latest prints the timeline. --show-prompts prints each request live. --trace-hashes keeps sizes and hashes only.
OpenTelemetry
--otel http://localhost:4318 sends a span per run, per model call and per tool call to any OTLP/HTTP receiver. --otel-content also attaches the conversation; send that only to a backend you trust.
Screenshots as evidence
--screenshots DIR saves a picture after every step and an index.html listing each step next to its picture. The model never gets these images. They are not redacted.
Video recording
--record-video DIR saves a WebM video of the browser, one file per page, when the run ends. Like screenshots, it is not redacted.

Using it from other tools

MCP server
selfbrowse-mcp gives Claude, VS Code and other MCP clients a browser: one browse(task) tool that returns only the answer, or step tools that return the numbered list. The same guardrails apply.
Python API
BrowseAgent(...) with guardrails, step callbacks, your own hand-off handler and your own model.

Honest limits

Selfbrowse is early software. These are the things we know it does not do well yet, or have not checked.

  • Research-style tasks learn little. Most of their clicks are specific to the question. A harder task in the demo shop, the cheapest item in each category, failed in all eight runs, with learning on or off.
  • One run per cell. All benchmark figures come from single runs on one local model, so a single difference is anecdotal.
  • AgentCore is unverified on real AWS. The adapter is tested against a stand-in for the AWS SDK and a local browser only.
  • Your own model routes for Azure OpenAI and AWS Bedrock are tested with a fake model, not live accounts.
  • Not supported yet: closed shadow roots, drag and drop, file uploads, and custom dropdowns beyond clicking them.
  • Guardrails reduce risk; they are not guarantees. Pattern matching for personal data and injection misses things. A hosted model still sees any page text you do not mask.
